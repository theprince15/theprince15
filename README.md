### 🔐 RateLimitEngine — *Distributed API Rate Limiter*
> `Golang (Gin)` `Redis` `Docker` &nbsp;|&nbsp; *Jun 2025*

A **production-grade distributed rate limiting engine** built in Go from scratch. Implements the **Token Bucket algorithm** for smooth, burst-tolerant request throttling. Supports multi-tenant rate limiting by **client IP** and **API key** simultaneously. Uses **Redis** as a shared state store for enforcing limits across distributed instances — ensuring consistency in multi-replica deployments.

**Key Highlights:**
- ⚡ Maintains **sub-2ms p99 latency** even under sustained high load
- 🔥 Benchmarked to handle **10,000 concurrent requests** without degradation
- 🐳 Fully containerized with **Docker Compose** for easy local dev and deployment
- 📋 Exposes metrics endpoints for observability and debugging

### 🛒 ShopHub — *Full-Stack E-Commerce Engine*
> `React.js` `Next.js` `Tailwind CSS` `Node.js` `Express.js` `MongoDB` &nbsp;|&nbsp; *Mar 2025*

A **full-stack e-commerce platform** built with a focus on **transactional reliability** and production-level security practices. The checkout flow integrates **Stripe Payments** with full webhook signature verification to prevent payment fraud. Database operations are wrapped in **atomic transactions** — if payment fails, cart reservations are automatically reverted, preventing inventory leaks.

**Key Highlights:**
- 💳 **Stripe Checkout integration** with webhook signature verification and idempotency keys
- 🔐 **JWT-based auth** with refresh token rotation and secure httpOnly cookies
- ⚛️ **Atomic MongoDB transactions** — cart reserve → payment → inventory deduct in one ACID unit
- 🎨 Responsive, mobile-first UI built with **Tailwind CSS** and Next.js App Router

---

### 📊 Placement Tracker — *Campus Recruitment Management System*
> `Java` `JavaFX` `MySQL` &nbsp;|&nbsp; *Nov 2024*

A **centralized campus recruitment tracker** with full **Role-Based Access Control (RBAC)** for three user types: Admins, Students, and Recruiters. The database schema is normalized to **Third Normal Form (3NF)** to eliminate redundancy. Careful use of **optimistic locking** and **batch processing** ensures no race conditions during high-concurrency registration periods (like placement drives with 200+ students registering simultaneously).

**Key Highlights:**
- 🔒 **RBAC system** with granular permissions — admins manage companies, students apply, recruiters post drives
- 🗄️ **3NF normalized MySQL schema** — optimized for concurrent registrations without locking contention
- 📈 **JavaFX dashboard** with real-time placement statistics and application tracking
- 📧 Built-in **notification system** for interview schedule updates and offer letter status
